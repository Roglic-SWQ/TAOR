# Stage 2 共享事实选择与 Stage 3 多视角生成

新任务默认使用 `shared_fact_selection_v1`。模型只选择一份共享事实集合：

```json
{
  "status": "ready",
  "selected_fact_ids": ["rf:2", "rf:3"]
}
```

示例 ID 仅说明结构。实际必须引用当前实体的 Stage 1 事实。`ready` 至少选择一条事实，最多 `max_selected_facts` 条，允许少于上限；证据不足时返回 `insufficient_evidence` 和空列表。选择应保留实体身份与重要关系，考虑目标模态，注重信息互补而非重复细节。

模型不返回候选组合、`focus`、事实角色、槽位、配额、逐事实分数或理由。未选事实保留在 Stage 1，不要求逐条重新分类。

`--max-selected-facts`（默认 64）只控制 LLM 精选的事实数量上限；`--relevance-fact-budget`（默认 64）控制粗筛后给 LLM 看的事实数；`--candidate-budget` 单独控制 Stage 3 的生成尝试预算。三个参数单位与职责不同，不相互填充。

## 事实和检查

程序从被选事实绑定原始内容和证据，拒绝未知事实、缺少证据或失效证据引用。新流程的 reranker
通过共享指令保留实体语义与关系，同时考虑目标模态；Query 只包含动态实体标签与目标模态。
`relevance_score` 表示任务相关性，不对照原证据做事实性检查。
默认 Stage 2 看到相关性排序前 64 条及其证据；提示词、JSON Schema 和引用校验使用同一组 ID。
完整事实仍保存在 Stage 1，`relevance_selection` 记录本轮视图；低相关性不等于事实错误。

Stage 3 的所有候选接收同一份原始三元组与证据。新流程不调用旧固定视角模板，不把事实拆成不同候选组合。图片提示词按顺序生成，后续调用读取本轮已接受的提示词，选择互补的表达重点；先前生成内容只用于协调，不能成为新证据。多视角不允许补造未知背面或俯视结构。SDXL 仍逐张调用。

文本默认生成一条完整描述；显式设置 `--candidate-budget` 可实验多条文本。图片默认运行预算为 3 次生成尝试，与正式批处理入口一致；可任意配置正整数，不是方法上限。旧通用 CLI 曾默认 5，历史测试脚本仍可显式选择 5。按大小写与空白归一后完全相同的提示词不会重复调用 SDXL，实际候选数可以小于预算。这不是语义去重或效果驱动的自动停止，语义相近的结果仍可能保留。

Stage 4 按共同事实集合构造所有候选的事实观察、语义参考和三元组对齐。2026-11-07 起，内部上下文使用 `selected_evidence_context_v2`：检查项统一放入 `checks`，不再划分必须／建议覆盖。文本和图片均允许合理省略；遗漏可影响语义覆盖，但不直接触发补写或补画。每项保留来源模态、证据引用和图片观察的范围／不确定性；身份上下文也不表示像素认证。

文本生成提示词使用 `entity_semantics_text_v5`：长度随事实内容调整，不再限制 1～2 句；从所选事实中组织相关且连贯的内容，保留主客体、方向、否定、不确定性、归属与时间等限定，并以目标实体为中心，将属性和关系综合成自然、连贯的描述。原始证据用于理解所选事实，身份上下文只用于有证据支持的名称与类型，不扩展候选事实范围。文本分支使用独立的简洁指令，仅在有反馈时附加修复要求。该版本写入实际文本请求和调用日志。

图片提示词使用 `entity_semantics_image_v4`：以目标实体为中心，把共享事实中的可见属性与可表达关系组织成连贯画面；非视觉关系用于身份识别，无须画成场景元素。构图和光照由 Stage 3 决定，不能改变事实。输出沿用三个字段与既有长度校验，真实外观未知时记录缺失并采用保守概念表现。格式修复保留当前候选的原事实和表达上下文；当前图片版本记录在请求与调用日志中。完整规则见 `docs/gpt4omini-prompts-v2.zh.md`。

实体身份约束仍来自有证据的 Stage 1 画像。图片计划仍需保守区分可见属性和非视觉背景；这部分由模型判断与后续观察共同处理，不声称程序已解决视觉可表达性。一次 Reflect 修复沿用原候选事实集，不重新规划角色或配额。

## 运行与兼容

Qwen 与 GPT 共用简单协议。Qwen 首次请求使用普通生成，格式修正使用小型 JSON 约束；GPT 请求使用 JSON Schema。最多两次完整计划修正，错误一次汇总，重复无效响应提前停止。网络瞬时故障默认额外重试一次，仍与业务修正共用 300 秒阶段总预算。

Stage 2 调用日志记录新协议版本、实际模型、每轮响应与错误；阶段产物只保留事实选择、上限及基础元数据。内部编译一个共享上下文供所有候选复用，不重新决定事实。旧角色／槽位协议保留在显式 `LegacyRelationPlanner` 和旧产物读取分支中，用于兼容测试与历史恢复，不参与新默认任务。

旧 `candidate_fact_plan_v1` 仍按原协议读取：恢复时保留原 focus、候选事实和图片字节。
`candidate_fact_plan_v2` 作为历史候选组合协议显式保留；默认新请求不再输出候选组合。新旧产物不会混写，共享事实计划允许保存恢复少于生成预算的图片，并复用原始图片字节。

已有任务如果使用独立源码快照，继续按其快照运行。本次没有重启批量任务或调用真实模型。离线测试验证协议、来源绑定、候选隔离、评分、修复以及新旧产物恢复；真实生成质量和成功率仍需另做模型对照。
