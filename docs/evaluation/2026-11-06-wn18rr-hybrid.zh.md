# WN18RR 混合评审：修正上游证据边界

本轮在 `judge-reflection-update-20261106` 的 `92dbee6` 上继续改进。先用零 GPU 的实际 API 复核，再顺序申请单卡验证。本地 Qwen2-VL-7B 继续承担图片描述、精简特征抽取、共享事实选择、文本与生图提示词生成；独立 API 承担图片准入、原像素属性复核和 Stage 4 Judge。Qwen3-Reranker、SBERT、CLIP、BLIP、SDXL 仍实际本地执行。**这是混合配置，不是纯 7B 能力提升的证明。**

## 改动与原因

- 新增可选 `--stage1-visual-verifier-config`。未提供时沿用原模型路由；提供后只替换准入和像素复核，不把生成偷偷换成 API。审核服务失败时保留已经完成的抽取与全部调用，标记来源验证未完成，不放行未验证事实。
- 为 WN18RR 的十一种关系附带明确语义。`hypernym` 表示 subject 的上位类别是 object；入边标记不会反转原始三元组。语义沿事实传到准入、选择、生成和 Judge，但不向原图感知提供图谱答案。方向依据 [WordNet 官方输入格式](https://wordnet.princeton.edu/documentation/wninput5wn)。
- 准入只依据可见属性冲突排除图片；非可见的分类争议保留为不确定性，不据此宣称图片错误。外观相容仍不等于身份验证。
- 生成只接收精选事实。完整机器描述、未精选图谱路径正文、像素审核说明中的附加细节保留在审计产物，不再作为额外生成事实。
- 对纯图片、已复核通过的实例属性，程序生成明确的样本范围 claim；保留原始 subject/relation/object、观察与引用，不把“这张图里的属性”提升成类别的普遍属性。已有作者 claim 和混合来源断言保持原样。
- 原图引用仅列原图，不混入其派生描述。唯一性、完整检查覆盖和来源校验继续严格执行，没有靠程序去重制造成功。
- 修复文本按大小写／空白归一后与原文相同，则标记 `repair_skip_reason=unchanged_text`、不可替换原候选。即使新一次 Judge 改口说已解决，也不能把原样返回算作文本修复；图片换种子不适用这条文字规则。

没有降低评分门槛、增设实体关键词特例或增大原生生成预算。源权重仍是选择政策信号，不是真实性概率；独立审核也仍是模型判断。

## 固定输入与实际失败

产物根目录：`outputs/wn18rr-hybrid-20261106/`。实体仍为 `02436645 / water deer`，train SHA256 为 `038612e783c215ee5f3ca9fbfca27b8d0739be1028fe4ee7c174aecf0b83d5df`，原图 SHA256 为 `0dc11e1b26f68c44209be5b764a02441ad1fc89a5030a98a501d6fb4899cc456`。补文本时隐藏源文本，补图时移除全部原图；未用隐藏定义纠正文本。每轮候选预算 1，SDXL 1024×1024、20 steps、guidance 7.5、base seed 20260708，实际候选 seed 20260709。配置、源码哈希、调用和生成图分轮保存。

零 GPU 作业 `taor-hybrid-cpu-1106-r1` 对上一轮原生 7B 的六项属性做独立复核：棕色、大耳、长口鼻保留；slender、short tail 不确定；hoofed 被模型判为冲突。这些是审核意见，不是人工标注的解剖学真值。

第一轮混合 GPU 作业 `taor-wn-hybrid-1106-r1` 执行完成，但质量失败：API 准入把 hypernym 方向读反，依靠不可见分类争议拒绝原图；本地文本还从未精选的路径扩写 Tragulidae、牛羊等内容。原始错误文本与评分未改写，不能把退出码 0 当作质量通过。

在固定原图与原始三元组的 API 控制中，加入关系语义和准入边界后，原图判为 compatible、身份未验证；同一段 r1 错误文本被 Judge 明确判为方向矛盾。产物在 `semantic-control-r2/`，与 r1 分开保存。这里改变的是输入协议，不是同提示词的纯模型对照。

第二轮 `taor-wn-hybrid-1106-r2` 补文本和真实出图均完成，完整 Stage 4 无评估失败。文本正确表达 water deer 是 mouse deer 的一种，未再扩写牛羊等背景；审核仅放行棕色和大耳。仍有把样本外观概括成物种特征的措辞，Stage 4 记录其不确定性，但没有触发 Reflect。该问题促成最后的样本范围 claim 与审核说明隔离修正。

图片评审将精确身份及完整地理栖息地断言保留为 uncertain，分类与“最大”保留为 unverifiable；事实一致性维度为 null，没有伪造满分。实际查看新图，为湿地中的鹿状动物，不能据此确认精确物种。

## 最后一轮：闭环执行了，文本修复仍然无效

`taor-wn-hybrid-1106-r3` 的文本与图片任务均退出 0、完整 Stage 4 completed；源目标未用于生成。补图实际生成新 PNG，SHA256 为 `afff5af46b6a30781ebc184aae65c1502bea4579e46d27e196859c8806b421ef`，与 r2 同像素；四项图片断言依次为 uncertain/appearance_only、uncertain/appearance_only、unverifiable、unverifiable，事实一致性仍为 null。图片没有为了不可见分类／地域断言强制重画。

本地文本最初仍泛化了棕色、大耳和长口鼻，还漏掉 mouse deer 上位类别关系。Stage 4 将三项图片属性判为 uncertain、关系判为 missing，并触发**真实的一次** `edit_text`；修复调用确实包含原文、固定事实及漏项操作。但 7B 返回与原文完全相同的文本。复评仍为三项 uncertain、一项 missing，`repair_outcomes` 为 unresolved、`repair_eligible=false`，最终保留原文。原始和修复候选、调用、两次观察均保存，不能报告“反思纠错成功”。

最后一轮文本记录 14 条模型调用（包含本地 reranker 记录），Stage 1 API HTTP 尝试 2 次；原文与修复文两次 Judge 合计收到 5 次响应，其中三次违反“没有可核验断言时事实分必须为 null”的合同，经现有有界修复才接受。两次 Judge 各耗时约 101 秒、129 秒，是最后一轮较慢的主要部分。图片任务一次 Judge、一次实际 SDXL 出图。逐轮记录计数在 `verification/execution-counts.json`；Stage 4 底层传输重试与 API 账单未完整暴露，不据此虚构完整成本或稳定性结论。

这说明明确证据范围有助于揭示错误，并不能保证 7B 执行编辑。r2 与 r3 的审核准入属性也有差异：长口鼻在 r2 未获支持、在 r3 获得支持；单次独立审核不是稳定真值。没有把这几轮分数当作统计质量收益，也没有据此扩大运行。

发现原样返回后补了上述确定性保护。新增保护在三个 GPU 作业结束后实施，只用 CPU 重放 r3 实际候选和观察验证：保留 text_001，text_safe_001 明确标记 unchanged_text。重放记录 `verification/actual-unchanged-repair-replay.json` 保留原始评分文件 SHA，未回写原运行。GPU 执行源码以各 attempt/execution.json 为准，不能把事后 CPU 验证说成重新跑过原生模型。

三个 GPU 作业与零 GPU 预检作业均已 Succeeded，最终状态保存在 `verification/jobs-final.json`；没有遗留本轮占卡任务。

## 复跑配置

在新申请的一 GPU 作业内运行下列入口；每次使用新的 attempt 名，已有目录拒绝覆盖。

```bash
TAOR_REAL_ARTIFACT_ROOT=/medisco/linjiashi/Code/TAOR/outputs/wn18rr-hybrid-20261106 \
TAOR_REAL_ATTEMPT=<新的运行名> \
TAOR_REAL_API_ENV_FILE=/medisco/linjiashi/Code/.env.standardization.local \
TAOR_REAL_PROXY_SETTINGS=/medisco/linjiashi/.config/taor-runtime/proxy-hybrid-20261106.json \
TAOR_REAL_VISUAL_VERIFIER_CONFIG=configs/independent-visual-verifier.yaml \
TAOR_REAL_STAGE4_CONFIG=configs/stage4-api-judge-gpu0.yaml \
timeout 3000 bash /medisco/linjiashi/Code/TAOR/scripts/run_wn18rr_real_test_cluster.sh
```

私有代理 JSON 位于 Git 外，目录 0700、文件 0600；只读取 `/root/.bashrc` 中已有的字面代理 export，不执行 shell 启动代码。API 密钥仍从用户指定的原始环境文件读取，不复制进配置、命令或 Git。wrapper 保持 doctor 的 JSON stdout，不打印私有配置内容。本入口目前明确限于一个冻结实体，不能直接称为十实体实验入口。
