# 视频／音频两步知识建模验证

Stage 1 已接入短视频与音频：先由模型生成描述，再结合描述与同一份原始媒体证据抽取三元组。
视频输入为带实际时间位置的采样画面和完整第一音轨，音频输入为原 WAV／MP3 文件。
多个已有媒体各生成一份描述，再统一提取，不增加独立事实性 rerank。

实现与格式检查通过，**模型感知准确性未得到保证，音频小例存在错误**。

## 真实 API 小例

使用用户授权的本地环境文件读取凭据，不在产物中保存密钥或 base64。
实际响应模型为 `gemini-2.5-flash`；未运行本地 Qwen 权重、相关性 reranker、SDXL 或 Stage 4。

| 输入 | 最终调用 | 输出 | 语义核对 |
| --- | --- | --- | --- |
| 合成 2 秒红屏转蓝屏视频，附带高音转低音 | 描述 1 次、提取 1 次 | 7 条三元组 | 识别出颜色顺序和音调变化；不能作为视频召回率结果 |
| Windows 本地语音合成的 “The museum opens at nine.” | 描述 1 次、提取 1 次 | 8 条三元组 | 转写正确，但错误报告了持续到片尾的 ding 声时间段 |

两步中的媒体字节指纹一致。当前代码重新解码视频后的输入指纹，也与实测请求一致。
视频与音频为独立运行，合并展示；不是一次联合处理两个来源的实验。

音频最终描述与事实把约 1.600–2.699 秒记作 ding 声；原始 PCM 在 2.2–2.6 秒的采样值均为零，
所以“持续到片尾”的时间断言错误。非语音事件本身的类别也未确认。两步都收到原音频，仍未纠正这一错误。
来源引用只说明模型依据什么输入，不证明判断正确；任务相关性 rerank 同样不能当作事实性验证。

最初运行还暴露了 Markdown JSON 包装、脱离目标实体的 speech／voice 三元组及漏原始来源引用。
现在媒体抽取请求使用 JSON 对象输出模式，提示词说明音频组成事实如何锚定目标，契约错误仍按原有有界流程修正。
未放宽目标锚定或来源检查，也未把错误样本删除。

原始请求／响应、完整事实和失败尝试保存在本地忽略目录：

- `outputs/explanations/av_two_step_case/trace.json`：最终两个小例及语义问题。
- 同目录 `trace-format-failure.json`、`trace-contract-attempt.json`：先前失败尝试。
- 同目录 `probe.json`：接口能力探测；遇到过模型有列名但无通道，以及 HTTP 200 却忽略原生视频的情况。
- 同目录 `verification.json`：检查结果与实际请求数量。

## 检查与边界

回归集 350 项通过、20 项排除：8 项历史提示词快照，12 项 Windows 下失败的旧 Bash 启动测试。
最后针对媒体、图片和三元组的检查为 63 项通过，与回归集重叠，不累加计数。`git diff --check` 通过。
覆盖相同媒体输入、视频后段画面、音轨与画面对齐、无音轨视频、共享预算、失败中止、
目标模态屏蔽、原始来源引用、产物保存及恢复时拒绝已变化的媒体文件。

当前视频约每秒采一帧，使用第一视频流与第一音轨，音轨转为单声道 16 kHz；短暂事件和空间声音可能丢失。
单文件和解码输入各限 7 MiB、时长限 120 秒；超限直接报错，尚未实现长媒体分段处理。
默认 Qwen2-VL 无音频能力，需要配置支持音频的 Stage 1 模型。
运行配置见 [Stage 1／2 运行文档](../stage1-stage2-runtime.zh.md)。
