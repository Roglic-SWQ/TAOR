## 提示词、Schema 与校验

沿用当前槽位规划业务规则、原始证据输入和修正反馈，千问调用版本标为
`qwen7b_stage2_candidate_slots_v3`。千问专用 system 提示词精简规则，删除示例中的假 ID，
末尾输出模板仅包含 plan 对象，逐事实列明合法角色和其自身证据 ID，避免复制说明元数据。
ready 模板直接展开 candidate_budget 个字符串槽位，要求填满各槽、必要时重复事实 ID；
insufficient_evidence 仍要求清空槽位。
输出顺序为 status、candidate_anchors、relation_plans，先决定实际槽位，再分配角色；
明确只有已锚定的事实可以标为 primary，其他事实必须选择 secondary/context/excluded。
它是 Stage 2 的专用规划提示词；
Stage 0 / 1 / 3 的 `qwen7b_original_v1` 原始模板保持原样。

模型仍须保留每条事实、选择角色及自己的证据引用，并为 ready 计划输出恰好
candidate_budget 个候选锚点。每次网络故障最多额外重试一次，业务修正最多两轮，
整个阶段共用 300 秒预算；支持关系单独出错时冻结已有合法角色和槽位。

本地 vLLM 使用普通生成接口和 1.05 重复惩罚，不发送 response_format 或 guided_decoding_backend。
当前安装的约束解码器在真实验证中速度较慢，并存在正则与长度限制组合的兼容问题。
因此普通生成请求通过额外提示词列出完整输出模板、全部事实 ID、合法角色及各状态的候选槽位数量，
明确要求纯 JSON、不带 Markdown，reason 为 5 至 15 词的简短英文句子。
后者是提示词要求，不是程序强制的词数限制。
原逐事实 Schema 和输入对话不被原地修改。输出字段、证据归属、每个事实恰好一次、
非空白 reason、角色、支持方向和冻结决策仍由共用本地校验器严格验证，失败时请求模型修正；
不通过删除事实、替换引用或补写模型输出让结果过关。
调用日志用 `wire_schema_version: stage2_qwen_prompt_json_v1` 标记本地输出方式，
每次网络请求记录实际追加的 `output_contract_prompt`。

每次本地请求先通过同一 vLLM 服务的 `/tokenize` 获取实际输入长度和模型上下文窗口，
将输出预算设为 3072 与剩余窗口的较小值，避免长输入或修正反馈导致 HTTP 400。
该步骤与生成请求共用单次总超时及阶段预算，token 数与实际输出预算写入审计。
不截断原始事实或证据。

显式传入 `--stage2-model-config configs/openai-gpt4o-mini-judge.yaml` 可做 GPT 对照，
脚本也支持 `STAGE2_MODEL_CONFIG`。远程 GPT 继续使用原逐事实 Schema。
