## Stage 1

- 本地千问对于可定位的引用错误、空 claim 和遗漏事实，仅返回所请求的字段／事实补答。
  事实以真实 ID 为键，字段以 JSON Pointer 为键；缺键、多键、重复键都拒绝。
- 合并从原回复副本开始，其他合法字段、claim 及来源绑定不变。模型仍须显式返回每项新值，
  合并后执行原有完整知识校验。未知／重复事实 ID 等无法安全孤立的错误走完整源数据重建。
- JSON 损坏时，从首次修正开始就用原始输入重建，不携带重复或截断的错误原文。
- 修正 Schema 限制非空 claim；画像 `evidence_refs`、属性 `source_ref` 使用原始证据 ID 枚举。
- 默认 Stage 1 总预算为 180 秒，网络重试与业务修正共用；单次请求只使用剩余预算，
  已耗尽时不再发起新请求。日志保存阶段时限、网络尝试和实际耗时。
- 本地千问启用字段补答；其他 `StrictJsonStagePlanner` 使用者保留完整替换接口，
  同样使用源数据修正和阶段总预算。

## Stage 2

David Greenwalt、Dean Martin 都出现过 4 个 primary、只有 3 个候选槽位的冲突。
旧定向修正在 primary 超过预算时直接放弃，完整重写后反复产生同一错误。

新增 `roles_and_slots` 补答，模型显式返回：

- `primary_fact_ids`：至少 1 项，数量不超过图片预算；
- `secondary_fact_ids`：其余冲突事实；
- `reasons`：每个被重新审查事实的简短理由；
- `slots`：预算对应的全部编号槽位。

两组事实 ID 必须互斥、无重复并完整覆盖待重分配事实。程序仅将这些明确选择转换回原角色表示，
不自动降级未回答的事实、不增加候选图。其他角色、证据引用、支持关系保留，最终执行完整规划校验。
