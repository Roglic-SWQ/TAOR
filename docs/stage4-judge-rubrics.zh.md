# Stage 4 四维 Judge 与定向修复

## 2026-11-07：评分协议去除格式性硬门槛（当前）

Judge 调用协议更新为 `candidate_observation_contract_v3`。四维分数、来源模态和不确定性保留，评分聚合公式不变。主路径只强制可用的四维分数、合法取值和可绑定的检查身份；原因、引用、观察完整性与分数之间的一致性不再决定整份评分能否解析。

| 原硬校验 | 当前处理 |
| --- | --- |
| 数值分必须附非空 evidence，且以 text:／pixel: 开头 | 接受空数组、普通引用与描述；不补前缀、不编造引用，空引用记入 `rubric_diagnostics` |
| 有 supported 就不许 F=null；无矛盾就只能 F=4 | 原始分数和 null 均保留；字段不一致只记诊断，不重新要求模型改分 |
| 每个 check_id／issue_id 必须全部返回 | 未观察的检查列为 unassessed；不虚构 missing，也不视为修复完成 |
| 单项 reason／confidence 缺少或证据模式冲突就整份失败 | 可用分数继续保存；没有可用依据／路由置信度的观察不能触发自动修改 |
| 无来源引用的删除建议或相互冲突的判断使整个评分失败 | 保留判断并记录诊断，禁用对应自动删改；建议本身不执行 |
| Judge 响应无效标为 malformed_candidate | 改为 `judge_response_invalid`，不将评分失败路由成内容重生成 |

保留合法 JSON、四维分值类型／0～4 范围、当前候选的来源与检查 ID、禁止未知／重复 ID 的基本校验。没有真实图片输入时不编造视觉评分。来源字段由控制器绑定，模型不能把图谱断言升级为像素证据。额外冲突可通过 `evidence_refs` 提供源 ID，兼容旧 `context:<ID>` 表达；外来引用不能授权自动删除。

评分有效、内容是否可用、是否有依据自动修改、原修复问题是否完成是不同判断。比如 E=0 且 evidence=[] 现在得到有效的语义拒绝，**不再是解析失败**；同样不能靠空引用启动自动改写。缺失固定修复问题或“resolved 但没有实际内容依据”不能获得替换原候选的资格。原始响应仍保存在调用审计中，诊断随 Stage4 候选保存。

## 2026-11-07：来源分明的事实检查与语义修复

当前观察协议为 `fact_observation_v2`、上下文为 `ranking_context_v2`、策略为 `targeted_reflection_v3`，融合版本为 `stage4_rubric_fusion_v6`。四维评分结构保持不变。

新主链移除 must／should 及逐检查的 requirement。所选事实是可使用的证据范围，不是逐项覆盖清单；文本遗漏和图片未展示都不直接触发添加操作。`source_modalities` 区分 graph、text、image 等来源，`evidence_refs` 绑定原始证据；图片的 `visual_observations` 保留 basis、范围、身份／特征不确定性。图谱断言不能充当像素观察，图片相容也不能认证图谱分类或身份。

有具体证据的事实矛盾／额外冲突在 Stage4 统一拒绝并进入现有定向修复；证据不足和不确定不冒充矛盾。导出只使用该最终状态及修复资格，不再额外要求存在必需项。语义评分为 0 且具有来源与实际候选证据时，会生成独立 `reframe` 操作。图片仍先审核原提示词，决定定向改写、原提示词新种子采样或因不确定而跳过；没有来源支持时不强制编造。语义问题以固定 issue_id 进入修复复核，不能只因下一轮漏报问题就认定解决。

修复问题由控制器绑定 `issue_kind`。未解决的 semantic 问题只用于语义复核，不强制改变事实分；没有可核验事实时仍允许事实分 null。Stage3 与 Stage4 都保存固定修复问题，恢复时校验候选父子关系、来源引用和原检查范围，不能因保存时漏列问题而跳过复核。图片观察在冻结后会转回普通 JSON 元数据以便校验，来源和不确定性不变。

历史产物只在 `mmkgc/io/legacy_evidence.py` 的读取边界转换：先核对原事实、引用及检查范围，再附加源事实的模态信息。原始文件保持不变。旧字段不能进入新请求或新产物。

下文保留此前版本的设计与验证记录；其中“文本必要事实遗漏触发修改”已由当前版本取消。

主流程由 `mmkgc/ranking/factory.py` 启用 `entity_modality_rubrics_v1`。继续使用现有 Judge 模型配置和 API，不指定新的服务商或模型名称。文本与图片各返回四个独立的 0～4 整数分，并附原因及候选内容证据。

| 维度 | 文本 | 图片 |
| --- | --- | --- |
| 实体语义 | entity_semantics | entity_semantics |
| 可核验事实一致性 | verified_fact_consistency | verified_fact_consistency |
| 语义覆盖 | semantic_coverage | visual_semantic_coverage |
| 表达可用性 | textual_usability | visual_usability |

提示词保存在 `mmkgc/ranking/prompts/`。图片判断必须收到真实图片；生成 prompt、预期描述和文件名不能充当像素证据。没有参考图时，语义相符不代表已核验具体实体的真实外观。

## 输出与事实边界

模型输出四个字段：`scores`、`observation`、`unverified_additions`、`repair_suggestions`。不再要求模型自由给总分、全局 confidence 或 hard_reject。

- `observation` 保留原有逐事实状态及逐观察 confidence，以兼容现有 Reflection。confidence 是路由信号，并非已校准的正确概率。
- `unverified_additions` 单独保存无法确认真假的新增信息。它们不自动降事实分、不获得额外覆盖奖励，也不自动进入删除任务。
- 原名 `unsupported_claims` 为兼容旧接口保留；新 Judge 只将有证据冲突的额外断言放入其中。必须同时引用实际候选内容和 `context:<已提供证据 ID>`，KG 沉默不构成冲突。同一错误已在 fact_checks 中请求替换时，不再重复请求删除。
- `repair_suggestions` 仅供审计，执行仍读取原有 observation。
- 缺失影响覆盖，不能当作矛盾。图片局部未展示的事实不能仅凭未出现就判缺失。无可核验断言时，事实分为 null；无已确认矛盾不应因遗漏降分；具体数值由 Judge 给出，程序不强行改成 4。

程序检查可用分值和检查 ID；状态与事实分的相容性记录为诊断，来源 ID 决定观察能否用于自动修改。这些检查只能验证输出约束，不能证明模型的观察正确或引用真正蕴含结论。

## 排序

记实体语义为 E、事实一致性为 F、覆盖为 C、表达可用性为 U：

1. Judge 语义分为 `(E + C + U) / 12`，上限为 `E / 4`；F 非 null 时，再以上限 `F / 4` 约束。
2. 原有文本/图片融合权重保留；融合后的候选分同样受 E/F 上限约束，避免相似度抵消已确认错误。
3. E=0 时由程序输出 `identity_mismatch` 拒绝；其他事实错误通过分项分数和既有逐事实反馈参与排序与修复。
4. F=null 不补成 0 或 4，产物标记事实核验范围不可用。高分只适用于已检查范围。

这是尚未经人工偏好或下游指标校准的初始聚合规则，版本为 `stage4_rubric_fusion_v5`，不是已证最优的权重。完整分项、上限及未核验新增信息保存在 Stage 4 候选产物的 `judge_rubrics` 中。

主流程拒绝缺少四维分数的旧式响应。独立构造 Judge 的默认行为和公共解析函数仍支持旧协议，供历史回放与旧调用方兼容；主流程 factory 显式启用新协议。旧 pair Judge 不在本次改动范围内。

## API 超时与平台兼容

主线程和工作线程统一复用 httpx 异步请求与总时限取消，不再使用 Windows 不支持的 SIGALRM。总时限覆盖连接和响应正文读取；即使服务端持续缓慢发送数据，也会在请求预算耗尽时取消并关闭响应。对外仍为原有同步调用接口，HTTP 状态分类与有界重试规则保持不变。

## Reflection：targeted_reflection_v2

继续只修复每个目标模态选中的一个候选，最多生成一轮。共享事实、事实来源和候选的父子关系保持固定，不回到 Stage 2 重新选择事实。普通观测协议保留，策略版本记录在 Stage 4 的 reflection_policy 和修复反馈中。

### 触发与修改位置

- 文本：有具体证据的矛盾，或必要事实的遗漏，可以触发定向修改。
- 图片：明确矛盾可以触发；仅仅没有展示某个细节，不自动补画，即使自报 confidence=0.99。缺失观察仍保留供覆盖评分及审计使用。
- 无法核验的新增信息继续单独记录，不自动删除。
- 没有具体 operations 的泛化反馈不启动事实修复。

对待修复图片，使用现有 Judge 追加一次纯文本 prompt 检查，不把生成 prompt 当作像素证据。它逐项核对原 prompt 是否已正确表达本次修复涉及的事实；肯定/矛盾观察须引用原 prompt 的实际文字。

| prompt 检查结果 | 执行动作 |
| --- | --- |
| 相关事实已经正确表达 | 原 prompt 原样保留，只重新生成一张图片 |
| 有明确错误或缺少所需指令 | 定向改 prompt，保留已正确指令、事实范围和合理构图 |
| 判断不确定、检查不完整或服务失败 | 跳过本次修复，保留原候选并记录原因 |

prompt 检查最多纠正一次响应格式；服务重试仍受原配置上限约束。它复用已有 Judge，不新增 Agent 或模型。初始多视角生成仍按原预算执行，修复只增加被选中候选的一次图像生成，不重跑多视角规划。

SDXL 原先按 ID 末尾数字派生种子，image_001 与 image_safe_001 会重复。修复 ID 现在额外使用完整 ID 的稳定哈希派生种子；初始候选种子不变，修复种子不同且可复现。不同种子不代表质量必然提升。

### 按固定问题验收

事实替换/补充沿用原 check_id。删除类任务另将原错误断言和 issue_id 放入修复候选的 repair_targets，复评时在同一次 Judge 调用中返回 observation.repair_checks，明确 resolved、unresolved 或 uncertain，并给出实际内容证据。原错误从新报告的 unsupported_claims 列表中消失，不单独算完成。

- 修复候选必须仍检查相同事实、来源与要求；缺少原父候选或擅自更换目标不能参与替换。
- 至少一个原问题得到明确解决；无法确认修复完成时保留原候选。
- 已核验正确的事实不能丢失，也不能引入新的明确冲突。
- 不接受从原来可用的文本/图片退化到 rubric 0～1 级不可用或严重受损的产物。
- 允许有可核验改善的部分修复；尚未解决的问题保留在 repair_outcomes 中。明确仍存在的删除问题继续计入缺陷，而非因新报告漏列就归零。

所有原候选保留，修复候选的 repair_targets、repair_outcomes 和 repair_eligible 进入阶段产物。Judge 仍可能误判，上述流程控制不等于事实判断已获得独立认证；confidence≥0.8 仍只是辅助路由阈值。
