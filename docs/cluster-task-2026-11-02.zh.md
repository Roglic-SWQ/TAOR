## 集群尚未 clone 时，从这里开始

在确认有写入权限且没有同名项目的工作目录中执行：

```bash
git clone --branch pipeline-refactor https://github.com/Roglic-SWQ/TAOR.git TAOR
cd TAOR
git status --short --branch
git log -2 --oneline
```

两份交接文档随实现快照之后的独立文档提交提供，分支 HEAD 因此可以不是 `74bcea4`。首次接手保留分支当前文档，先阅读本文件与 `docs/cluster-handoff-2026-11-02.zh.md`；不要立即 checkout 到旧实现提交而把交接文件从当前目录移走。对照版本另建 worktree。

先只读盘点 GPU 分配、既有任务、Conda／Python 环境、MKG-W 数据、模型和本地 API 配置位置。权重、真实数据、凭据和完整 API 实验产物不会随 clone 下载；已有资源路径要在现场核对。不要输出凭据内容，不覆盖已有目录或重启旧 job。

没有交接压缩包也可以先做代码检查、针对性回归和环境盘点。下面的空截断响应可按已列字段构造最小回归；完整历史 API 原始记录另行传输后再核对，不是开始工程工作的前置条件。

## 已确定的设计，继续保持精简

1. Stage 0 保存完整合法一跳图谱目录，保留原始主客体和方向；不在入口按文件顺序截到 32。
2. Stage 1 统一成有来源的 subject／relation／object 事实。图谱由程序保留；文本抽事实；图片先模型描述、再同时看原图和描述转事实，视频／音频同理。描述不是独立证据。
3. Rerank 是实体语义、重要关系与目标模态用途的粗筛，给 Stage 2 看默认前 64 条；不是事实性评分，完整目录保留。
4. Stage 2 只返回 `status` 与 `selected_fact_ids`，选择一份共享事实，默认最多 64，允许少选。不恢复 primary／secondary、focus、候选组合或槽位配额。
5. Stage 3 同一组事实驱动全部候选。文本默认 1 条、不限 1～2 句；图片默认 3 次，协调表达并用 SDXL 出图。前序生成只协调，不是证据。去重仅大小写／空白归一后的完全重复。
6. Stage 4 使用相同共享事实参照；一次有条件的 Reflect 保持原事实集。模型说有问题不等于必然淘汰；相关性分数也不是真实性。
7. 主 CLI 当前只支持缺 text／image；视频和音频已有来源建模代码，不代表已有对应生成与真实数据适配全链路。

## 先完成的工程工作

**P0：响应分类。** 构造 HTTP 200、`finish_reason=length`、空 content 的最小响应回归，原始记录可用后再核对；应在 JSON 解析前识别截断，保留预算／usage／候选和模型信息，有界修复。不要因为替代 API 的问题把原生 Qwen 的默认预算无差别改大。

**P0：候选隔离与保存。** 复现第一个候选成功、第二个失败、第三个成功。保留已完成的提示词／图片／调用，继续剩余候选，支持恢复；全部失败才明确失败。不要靠实体级 `--continue-on-error` 掩盖候选级缺陷。

**P1：生成边界。** 修正把“有钟楼”扩成“与主体相连”、把“获奖”扩成“演出后领奖”等无依据细节。允许构图／光照选择，实体结构和具体事件须有来源；避免长串特例。顺带处理文本使用 Markdown 的小格式问题。

每个修复先有最小复现和针对性检查，保存修复后的新 commit。旧快照和旧任务保持原样。

## 然后做真实实验

先只读核对集群 GPU 分配、既有环境／任务、权重和数据，不覆盖正在运行的 job。`scripts/run_qwen7b.sh` 会覆盖 CUDA 掩码，必须先确认调度器分配；仅暴露一张流水线 GPU 时进程内设备写 `cuda:0`，使用对应 Stage 4 配置。

使用本地 Qwen2-VL-7B、Qwen3-Reranker-4B、SDXL，先 doctor，再单实体补文本与真实出图。Stage 4 judge 的凭据仅放集群本地环境，不能写 Git 或日志。模型／数据不在仓库，需要单独准备。

冻结 10～20 个真实实体、合法 train 证据、隐藏目标策略、共同事实 panel 和全部配置，图片比较三组：

| 组 | 内容 |
| --- | --- |
| `old_pipeline` | 固定旧提交，显式同为 3 次图片预算 |
| `new_shared_same_prompt` | 新事实处理＋共享精选事实，一个提示词、三个 SDXL 种子 |
| `new_shared_multiview` | 完全相同的精选事实，协调三个提示词、相同种子列表 |

后两组共用冻结的 Stage 1／2 文件及哈希。same-prompt 组尚无现成 CLI 开关，需要小型实验 harness 直接对冻结提示词运行三个种子；不要把生产去重当成三个真实出图调用。

文本先旧／新各一条。原始 Stage 3 与 Reflect 后结果分开，失败、跳过、实际调用数与成本全保留。不只展示最佳图；按实体统计，三张图不是三个独立实体样本。

评价共同事实覆盖／错误、无依据断言、真实图片可见属性与身份、画质、集合冗余和有用互补性。真实像素必须看；非视觉事实不能一律因没画出来判错。自动 judge 辅助并复核，不能拿两版各自的内部融合分数直接证明新版更好。

## 已有结果只支持到什么程度

- 上传前最终专项 134 passed；扩大扫描新版 974 passed／178 failed，对照旧版无新增失败 ID。不是全库通过；Linux 上还需检查当时因 Windows 未执行的范围。
- 四个合成案例真实 API Stage 0～3：文本两版均完成，新版共同事实覆盖 23/23、旧版 10/23，由 agent 逐句核对，不是独立人工基准。
- 原图片提示词 384-token 轨道旧 3/4、新 1/4 完成，失败是推理耗尽 token 后空输出；双方 2048-token 补充诊断均 4/4。两轨分开报告。
- 生成 API 返回 gpt-5.6-luna，不是本地 Qwen；没有 SDXL 真图，没有生产 Stage 4／Reflect 或下游 KGC 指标。
- 新提示词仍有无依据空间细化，三视角收益未建立；外部 judge 16 次有 7 次不合合同，不能用其自动分数当主结论。

原始证据在交接包的 `outputs/comparisons/2026-11-02-old-new-api-pilot/`，Git 不含这些文件。历史脚本写死 Windows 凭据路径，不直接当 Linux 原生模型启动器运行。

## 交付与停止条件

交付修复提交、必要回归检查、集群环境和模型／数据指纹、冻结实体与事实 panel、可复跑脚本、全部阶段与真实图片、失败／成本统计、逐实体并排报告。所有结果明确实测、失败、未测。

若单实体链路、来源遮蔽、候选保存或评审参照还不成立，先修这些问题；不启动 4580 全量。若小实验没有优势或多视角只是换措辞，直接报告证据，不通过筛掉失败样本制造改善。
